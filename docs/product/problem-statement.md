# Problem Statement · 青蚨使

**Dogfood 假设（ADR 002）**：主用户为「个人开发者 / 重度使用 AI Agent 办事的人」；以作者自用为第一证据源，满 4 周或 20 笔确认后回写本页。

## Problem Framing Narrative

**I am:** 个人开发者（或独立创造者）
- 用多个 AI Agent / 助手完成真实任务（订购、调用付费 API、小额采购）
- 没有支付牌照，钱只能走支付宝 / 微信 / 银行
- 担心 Agent「自作主张」扣款，又厌烦每一步都手工打开各 App 结账

**Trying to:**
- 让 Agent **提议**该付什么，我在看清金额/用途/收款摘要后 **确认** 再付款，且全过程可查、可停、可发起退款

**But:**
- 现有大厂 Agent 支付要么封闭在自家账户生态，要么强调额度内自付；开源侧缺少「只做人确认链路」的完整控制面
- 自己拼 webhook / 订单号时，没有统一的提议→确认→执行→审计→退款请求模型

**Because:**
- 信任问题尚未被「开源、可自托管、挂持牌通道」的中间层解决；静默自付在意图确认不可靠时风险过高（ADR 001）

**Which makes me feel:**
- 想用 Agent 办事却不敢授柄；要么全手工，要么闭眼赌

## Context & Constraints

- 无支付牌照；执行与退款必须经持牌通道（001）
- 前期禁止静默自付（001）
- 开源、可自托管；V1 单机单主理人
- 中国语境：V1 首轨支付宝 sandbox（003）；微信后置

## Final Problem Statement

个人开发者希望 Agent 能完成需付款的真实任务，但在意图与算法未可靠确认前，不能把「无人确认即扣款」交给 Agent；他们需要一个开源、可自托管的控制面：Agent 只提议，人确认后再走持牌通道付款，并始终看得见、关得掉、查得到、退得了（退款请求）。
